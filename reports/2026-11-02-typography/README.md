# Craftbaseと書体を揃える

本人指定：「フォント自体もAI感が出てしまっているので、今のcraftbaseのページの書体に合わせられるといい」。前の公開委任を引き継ぎ、featureブランチ・PRを経由して反映する。

## チーム検討と前回の振り返り

公開済みCraftbaseのCSSを直接確認した。日本語優先の指定は `"Hiragino Sans", "Noto Sans JP", "Yu Gothic", system-ui, sans-serif`。

Prompt NotesにはLP独自のHiragino Kaku Gothic ProN指定と、body/Tailwind側のGeist Sans指定が併存していた。前回は利用開始・保存・再訪の改善と公開はできたが、画面をまたぐ書体の一貫性の確認が不足していた。

チームの読み取りレビューでは、正確な書体列を単一変数に集約し、body・LP・Tailwind・フォームへ適用することを優先した。Craftbaseも見出しは700で、字間はPrompt Notes以上に詰まっているため、太さと字間は今回維持する。コードや記号の桁揃えも維持する。

再発防止の学びはAGENTS.mdに追記。今回は表示上の変更なので、実装を写した新規ユニットテストは追加せず、既存回帰とブラウザでの表示・入力確認を使う。

## 実装

- `--font-product-sans` にCraftbaseと完全に同じフォント優先順を定義。
- body・Tailwindのfont-sans・紹介ページで共用。Geist Sansとbodyのインライン上書きを除去。
- 一般の操作・説明・検索・編集本文・変数への入力はfont-sansへ統一。
- コード、Markdown記号、変数名の記法、URL・キー・IDなど桁を揃える表示には等幅を維持。
- 書体以外の文言、配色、レイアウト、認証・保存・料金は変更しない。

フォント列を同一にする変更であり、OSに搭載されたフォントによる描画差までなくすものではない。外部の日本語Webフォントは新たに配信していない。

## 公開前の検証

- 既存回帰17/17成功、TypeScript成功、lintは0 error・既存7 warning、Next.js 16.4.3本番ビルド成功。
- 320 / 390 / 768 / 1024 / 1440 / 1920pxのLPに横はみ出し・画面外の主要リンクなし。
- 実ブラウザの計算済みスタイルで、body・LP・見出し・ボタン・登録フォーム・ノート入力本文が同じフォント列であることを確認。
- 長い日本語とコードを入力し、Markdownプレビューのコードが等幅・改行維持となること、保存後に一覧へ戻ることを確認。
- 公開前後の画面、Claudeの読み取りレビューはこのフォルダに保存。

## Claudeのレビューへの対応

[原文](claude-review.md) は実際のClaude Codeを読み取り専用で実行した結果。公開を止める不具合なしとの評価に加え、確認事項を次のように処理した。

- Craftbase側のWebフォント配信：公開HTMLに外部スタイルシート、Google Fonts、font-faceの指定がないことを確認。両サイトとも同じOS上のフォント優先順を使う。
- バージョン履歴の本文：一般の入力本文と同じ書体へ揃えた。コードとしてのMarkdownプレビューは等幅のまま。
- 確認メール宛先：プロフィールと同じ画面書体へ揃えた。
- READMEのGeist Sans説明：共通変数とGeist Monoの用途を記載。
- レビュー原文が空という指摘：レビュー実行中は出力先ファイルが空だったため。完了後の原文は保存済み。

## 公開経路

前回と同じくPreviewはSupabaseの環境設定がなくビルドできない。設定を変更せず、ローカルの本番ビルドと表示確認を根拠にPRをマージし、既存Production設定での成功後に本番の書体を確認する。
